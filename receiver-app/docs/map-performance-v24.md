# 地图平移、缩放与中文对照修复

## 查明的问题

2026-09-27 的浏览器实测发现：缩放过程中同一个 z14 地图块被多次请求（包括预加载与绘图引擎请求），新增建筑数据每块约 400KB（压缩传输仍约 250KB）。海外链路慢时，重复请求、字体请求与新区域请求相互竞争。原来的默认行为会在放大时取消尚未加载好的较粗层级，细图尚未到达时更容易出现空白。

## 修复

- 同一地址的请求合并；地图字节采用 24MiB / 160 项上限的内存缓存，向绘图线程交付独立副本，避免 ArrayBuffer 转移后缓存失效。
- 同时下载最多 6 项，优先可见道路；空闲后有限预取附近与父层级底图，后台预取最多同时 2 项。不是下载整个国家。
- 保留正在加载的较粗地图，细节到达后逐步替换；保留 1 秒进场动画。
- Overture 缓存命中不再先等待远程版本目录；并发版本目录请求合并，失败短期退避。不会无限重试。
- 新增牙科、洗衣、学校、药店等类别对应，支持分类层级回退与更多中文语言字段；补充廊曼周边真实数据中出现的英文名称参考译名，保留原名与 † 标记。
- 双语缓存路径使用 v2，避免旧数据的浏览器缓存影响修复。

## 数据边界

抽样区 Overture 原始文件有 564 个地点，所有名称均只有 primary，未发现 common 多语言字段。数据能补充真实建筑轮廓与商铺，不代表已有全部中文译名。当前只在有数据中文名或人工对照词典时显示中文名称；其余保留原名与中文场所类型，不把类型说明冒充地名翻译。译名仅用于展示，不参与坐标、导航或误差计算。

查阅的官方文档：
- https://docs.overturemaps.org/schema/reference/common/names/
- https://docs.overturemaps.org/examples/overture-tiles/ （上游 PMTiles 是数据检查用途，不能直接等同生产底图）
- https://docs.protomaps.com/basemaps/localization （支持多语言字段，未承诺每个地点都有每种译名）
- https://docs.maptiler.com/schema/planet/ （多语言同样以名称数据可用为前提）
