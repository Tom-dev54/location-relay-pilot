# 海外地图接入与验证

本次改动使用“大陆高德，其他地区 MapLibre 矢量地图 + Geoapify；不支持矢量渲染的浏览器使用 Leaflet 高清图片兼容模式”的方案。两个正式入口保持不变，公开位置、旧私人位置和发送流程不迁移。Geoapify Key已配置为服务端secret，真实服务验收已通过；正式发布状态见交付目录中的发布结果。

## 配置步骤（本次已完成）

1. 打开 https://myprojects.geoapify.com/ ，注册或登录，创建一个项目，选择免费方案。**成功标志：进入项目页面；没有购买付费套餐。**
2. 打开项目的 API Keys，复制这个项目的 Key 交给维护者。它不是高德 Key。**成功标志：维护者取得 Geoapify Key，用于后台配置。**
3. 维护者将其作为 Sites 运行环境中的 secret 保存，名称为 `GEOAPIFY_API_KEY`。不能写进网页、Git、发布说明或 `.openai/hosting.json`。**成功标志：配置接口仅返回 `configured: true`，网页源码与浏览器请求中没有 Key。**
4. 维护者使用真实服务验证地图图片、地点查询、驾车路线，全部通过后发布。**成功标志：接收端选中泰国测试点有实际道路底图；地名来自实际查询；查询失败有明确提示；国内高德回归正常。**

没有 Key 时不能完成 Geoapify 的真实接口验证。当前不会把官方示例或网上别人的 Key 当成你的生产 Key，也不会把模拟图片当成可用海外地图发布。

## 已实现的行为

- 从坐标判断服务区域，不用浏览器语言、IP或粗略经纬度矩形。Natural Earth 1:10m 区域数据仅作服务选择参考，边界附近（至少5公里）给出手动切换提示。港澳台默认海外服务；GCJ02旧记录保持高德。
- 海外使用原始WGS84，不调用高德转换。高德仍使用原有转换；查询缓存按服务、坐标系、坐标及修订区分。手动选择只影响查看，不修改存储坐标。
- 海外地图显示标记、缩放、设备报告精度圆和来源署名。地点查询与地图绘制独立，地点失败仍画点；重试地点不重新加载底图。
- 真实返回的建筑/地点名称可加“附近”；仅当返回标注点在300米内才给方位与直线估算。没有名称时使用真实街道/片区；报告精度超过200米不指认具体建筑。非中文名称可保留原文，不编造翻译或建筑。
- 国内外均提供高德导航；海外另提供 Google、苹果地图导航，目的地使用原始坐标，起点由外部地图使用查看者位置。网页驾车路线仅在点击时请求查看者位置，起点和路线不保存到公开记录或数据库。
- 地图脚本、底图、地点和路线独立报错；授权失败、额度限制、连接失败、超时和无结果有相应提示。显示marker并不被当作底图加载成功。
- 切换地图销毁旧实例；失效的地点/路线回调不覆盖新选择；地图切换过程禁止继续操作已销毁实例。

## 接口与调用控制

- `GET /api/world-map/config`：只返回是否配置与服务名。
- `GET /api/world-map/place?lat=…&lon=…&accuracy=…&crs=WGS84`：返回已归一化的地点描述。
- `GET /api/world-map/vector/{z}/{x}/{y}`：矢量地图数据，原生层级0–14，前端可继续清晰放大。
- `GET /api/world-map/tile/{z}/{x}/{y}` / `tile-hd`：兼容模式普通/高清图片，层级0–19。
- 图标与常用拉丁/泰文字体随网页发布；其他字形从限定路径代理，中文由设备字体绘制。
- 中文名称来自地图数据中的 `name:zh`，同时保留当地原名，不自动翻译未收录地点。
- `POST /api/world-map/route`：同源JSON `{start:{lat,lon},end:{lat,lon},crs:"WGS84"}`；返回路线折线、米数和秒数，响应禁止缓存。
- Key只加入固定的 `api.geoapify.com` / `maps.geoapify.com` 请求，不允许任意目标URL或跟随重定向。原始上游错误不透传，避免泄露Key。
- 地点共享缓存7天，底图片段缓存24小时；错误和路线不缓存。调用上限为地点/路线合计每日300、每月5000次；底图片段每日2000、每月20000次。独立于高德计数，缓存命中不扣本站计数。
- 上限是本网站请求数，不是Geoapify实际计费积分；同账号其他项目调用不在此限制内。免费套餐规则以你的服务控制台为准，本次不启用付费。
- 不需要新增或修改数据库表，复用已有地图缓存与计数表，不改变位置保留7天的规则。

## 验证边界

自动化测试分为：区域与原始坐标检查、缓存/授权/额度/输入检查、本地真实接收接口、浏览器与真实Leaflet组件的模拟服务流程。模拟测试不能证明实际泰国地点覆盖或两机场内的建筑识别，也不能替代iPhone/Android与微信的真机导航。

2026-09-27已完成：

- TypeScript检查、生产构建、68项单元/真实SQL测试通过。
- 本地真实Worker公开接口11项、旧私人接口24项通过；原定位发送/改善/跨端浏览器流程18项通过。
- 新海外浏览器流程21项通过：真实Leaflet，其他服务模拟；涵盖反复切换、晚到路线、缺Key、瓦片额度错误、地点无结果、独立重试与390px宽度。
- 真实Geoapify：泰国测试点、廊曼与素万那普机场公共参考点的地点接口均HTTP200；真实PNG底图片段首次及缓存读取成功；浏览器完整16片底图加载，无失败瓦片；真实路线返回1889米、约277秒。
- 测试点实际返回“Krispy Kreme附近”，是附近POI，不认定用户就在该店或建筑内；机场参考点返回周边地址，不强行改写成机场名。
- 真实高德：在已授权站点域名下使用本地新版前端，玉林返回名人酒店附近、北京返回剧院办公楼附近；底图完成，驾车路线约2公里、10分钟。localhost不在原高德域名白名单内，因此没有放宽白名单，而是在原获准域名环境下测试。
- 修复真实联调发现的路线语言参数不兼容、地图缓存响应头不可改、已销毁地图的晚回调/动画，以及高德错误回显安全字段的问题。

真实接口测试仍使用本地注入记录和路线起点，没有把测试记录写入生产公开位置表。iPhone/Android实机定位、微信唤起和实际建筑入口仍待现场核验；不承诺每个海外坐标都能返回建筑名。
